# 홀덤 장부 (웹 버전)

Render에서 돌아가는 웹앱입니다. 데이터는 기존 구글 스프레드시트 **"홀덤 장부"**에 저장되고, 화면과 계산 방식은 예전 HTML 버전과 같습니다.

```
브라우저(아이패드/PC/폰) ──▶ Render 서버(Node.js) ──▶ 구글 시트 (서비스 계정)
```

---

## 1. 무엇이 바뀌나

| | 예전 (HTML) | 지금 (웹) |
|---|---|---|
| 접속 | HTML 파일을 열어야 함 (아이패드는 열기 어려움) | 주소 하나로 어디서나 접속, 홈 화면 추가 가능 |
| DB | `latest` 탭 한 칸에 전체 JSON (한 칸 최대 5만 자 → 날짜 약 10~11개에서 한계) | 날짜당 1행 + 섹션별 탭으로 나눠 저장, 칸마다 값 1개 |
| 덮어쓰기 위험 | 옛날 파일을 열고 아무 칸이나 건드리면 최신 데이터가 덮어써질 수 있었음 | 서버가 날짜별 버전을 확인해 다른 기기의 최신 수정을 덮어쓰지 않음 |
| 백업 | history 탭 (수동) | backups 탭: 수동 + 자동 (하루 첫 저장 전 / 날짜 삭제 전 / 복원 전) |

## 2. 새 DB 구조 (같은 스프레드시트에 새 탭 추가)

기존 `latest` · `history` 탭은 **읽기만 하고 절대 수정하지 않습니다.** 원본 그대로 보관됩니다.

| 탭 | 한 행 = | 주요 열 |
|---|---|---|
| `days` | 날짜(회차) 1개 | day_id, 순서, 날짜명, 숨김, 참가자수, 바운티풀비율(%), 부 개수, 버전, 최종수정 |
| `participants` | 날짜 × 참가자 번호 | day_id, 번호, 이름, 참여(참고) |
| `ratios` | 날짜 × 등수 | day_id, 순번, 등수명, 일반게임비율(%), 바운티게임비율(%) |
| `rounds` | 날짜 × 부 | day_id, 부, 게임유형(바운티/일반) |
| `buyins` | 날짜 × 부 × 참가자 | day_id, 부, 번호, 바이인, 리바인1~4, 합계(참고) |
| `rank_results` | 날짜 × 부 × 등수 | day_id, 부, 순번, 참가자번호, 상금(참고) |
| `bounty` | 날짜 × 부 × 등급 | day_id, 부, 순번, 등급명, 비율(%), 최대개수, 1번~9번(획득 개수) |
| `settlement` | 날짜 × 참가자 | **최종 처리금액** — 총 바이인, 부별 상금/바운티, 최종 처리금액 (계산 결과 기록) |
| `meta` | 설정 1개 | 부 개수, 부 이름 등 |
| `settle_runs` | 정산 1건 | 정산ID, 정산일시, 정산명, 상태(완료/취소), 포함 날짜, 합계확인 |
| `settle_totals` | 정산 × 이름 | 이름별 **합계금액**, 참여 날짜 수 |
| `settle_details` | 정산 × 날짜 × 참가자 | 날짜별 최종처리금액 (정산 당시 금액) |
| `backups` | 백업 1개 | 저장시각, 이름, 종류, 데이터(JSON) |

- 열 이름에 **(참고)**가 붙은 열과 `settlement` 탭은 보기 편하라고 서버가 매번 다시 계산해 쓰는 칸입니다. 직접 고쳐도 다음 저장 때 다시 계산됩니다.
- `days` 탭의 **보정데이터** 열은 평소에는 비어 있습니다. 위 구조로 표현되지 않는 값이 생기면 여기에 원본을 그대로 담아, 어떤 값도 사라지지 않게 합니다.
- 앱이 관리하는 탭에는 메모를 적지 마세요. 저장할 때 탭 전체를 다시 씁니다.

## 3. 정산 (여러 날짜 합산)

☰ 메뉴 → **🧾 정산**

1. **새 정산**: 정산할 날짜를 체크하면 같은 이름끼리 각 날짜의 *최종 처리금액*을 더한 표가 바로 나옵니다. (합계는 이름 바로 옆 열)
2. 정산 이름을 확인하고 **정산 완료로 저장** → 시트의 정산 이력 탭에 그 시점 금액으로 기록되고, 포함된 날짜 탭과 📅 전체 날짜 목록에 **정산** 배지가 붙습니다. (정산된 날짜도 탭에서 빠지지 않음, 배지에 마우스를 올리면 정산명 표시)
3. **정산 이력**: 지난 정산을 보고, CSV로 받거나, **정산 취소**할 수 있습니다. 취소해도 기록은 "취소됨"으로 남고, 그 날짜들은 다시 정산할 수 있게 됩니다.

규칙
- 이름은 **앞뒤 공백만 무시하고 정확히 같은 글자**일 때 같은 사람으로 합칩니다. ("홍길동"과 "길동"은 다른 사람) 비슷한 이름이 있으면 화면에 경고가 뜹니다.
- 이름이 비어있는 참가자, 같은 날짜에 같은 이름이 두 번 있는 경우는 저장할 수 없습니다.
- 이미 정산된 날짜는 다른 정산에 넣을 수 없습니다(이중 정산 방지). 다시 정산하려면 기존 정산을 취소하세요.
- 저장 금액은 서버가 시트 데이터로 다시 계산하며, 화면에서 본 금액과 다르면 저장하지 않습니다.
- 정산 뒤에 그 날짜 금액을 고치면 **정산** 배지가 주황색으로 바뀌고, 정산 창에 **정산 후 변경**이 표시됩니다. 원래 금액으로 되돌리면 다시 원래 색이 됩니다. (이력 금액은 정산 당시 그대로)

## 4. 데이터 보호 장치

1. **불러오기 전 저장 금지**: 서버에서 최신 데이터를 정상적으로 받기 전(또는 실패하면)에는 저장하지 않고 화면 위에 안내가 뜹니다.
2. **바뀐 날짜만 저장**: 날짜 삭제는 "삭제" 메뉴를 눌렀을 때만 일어납니다. 일부 날짜만 보이는 기기가 저장해도 나머지 날짜는 그대로입니다.
3. **버전 충돌 차단**: 다른 기기가 먼저 고친 날짜를 덮어쓰려 하면 서버가 거절하고 "최신 데이터 불러오기" 안내를 띄웁니다.
4. **쓰기 전·후 검증**: 쓰기 전에 메모리에서 쓰기→읽기를 흉내 내 원본과 비교하고, 쓴 뒤에는 시트를 다시 읽어 비교합니다. 다르면 저장을 잠그고 알립니다.
5. **한 번에 쓰기**: 한 번의 저장은 모든 탭을 하나의 요청으로 씁니다. 중간에 끊겨 반쪽만 저장되는 일이 없습니다.
6. **자동 백업**: 하루 첫 저장 전, 날짜 삭제 전, 복원 전.

## 5. 설치 순서 (처음 1회, 약 20분)

### ① 구글 클라우드: 서비스 계정 키 만들기

1. https://console.cloud.google.com 접속 → 상단에서 **새 프로젝트** 생성 (예: `holdem-ledger`)
2. 왼쪽 메뉴 **API 및 서비스 → 라이브러리** → `Google Sheets API` 검색 → **사용**
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → 서비스 계정**
   - 이름: `holdem-ledger` → 만들고 계속하기 → (역할은 선택하지 않아도 됨) → 완료
4. 만들어진 서비스 계정 클릭 → **키** 탭 → **키 추가 → 새 키 만들기 → JSON** → 파일이 다운로드됩니다.
   - 이 파일은 비밀번호와 같습니다. 다른 사람에게 보내거나 GitHub에 올리지 마세요.
   - 회사 계정에서 키 만들기가 막혀 있으면 개인 구글 계정으로 프로젝트를 만드세요.
5. 서비스 계정의 이메일 주소(`...@...iam.gserviceaccount.com`)를 복사해둡니다.

### ② 구글 시트를 서비스 계정에 공유

"홀덤 장부" 스프레드시트 → **공유** → ①-5의 이메일 주소를 **편집자**로 추가 (알림 보내기 체크 해제)

### ③ GitHub에 코드 올리기

1. https://github.com → **New repository** → 이름 `holdem-ledger`, **Private** 선택 → 만들기
2. **uploading an existing file** 링크 → 이 폴더의 파일을 전부 끌어다 놓기 → Commit
   - `node_modules` 폴더는 올리지 않습니다 (Render가 알아서 설치).

### ④ Render에 배포

1. https://render.com → GitHub 계정으로 로그인
2. **New → Web Service** → `holdem-ledger` 저장소 선택
3. 설정
   - Runtime: **Node** / Build Command: `npm install` / Start Command: `npm start` / Instance Type: **Free**
4. **Environment Variables**에 아래 4개 추가

| 이름 | 값 |
|---|---|
| `SPREADSHEET_ID` | `1GBdhWOCx3fpIxX3Yz30wNIfRvSJmQBXOE0zTCkll69E` (시트 주소의 `/d/` 와 `/edit` 사이) |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | ①-4에서 받은 JSON 파일을 메모장으로 열어 **내용 전체**를 붙여넣기 |
| `ADMIN_PASSCODE` | 관리자 페이지 비밀번호 (직접 정하기) |
| `APP_PASSCODE` | (선택) 장부 접속 비밀번호. 비워두면 주소를 아는 누구나 접속 |

5. **Create Web Service** → 몇 분 뒤 `https://holdem-ledger-xxxx.onrender.com` 주소가 생깁니다.

### ⑤ 기존 데이터 이전 (1회)

1. `https://(내 주소)/admin` 접속 → 관리자 비밀번호 입력 → **연결 상태 확인**
   - "구글 시트 연결 정상"이 떠야 합니다. 안 되면 ② 공유와 ④ 환경변수를 확인하세요.
2. **미리보기 · 검증** → 날짜별 요약과 "검증 통과: N개 날짜, N개 값이 1글자도 다르지 않게 복원됩니다"를 확인
3. **새 구조로 이전 실행** → "이전 완료 · … 모두 일치" 확인
   - 시트에 새 탭들이 생기고, 원본 JSON은 `backups` 탭에도 한 번 더 저장됩니다.
   - 새 탭에 이미 데이터가 있으면 이전 버튼이 막힙니다(덮어쓰기 방지).
4. `https://(내 주소)` 를 열어 날짜들이 그대로인지 확인
5. 아이패드 사파리: 공유 버튼 → **홈 화면에 추가**

### ⑥ 이전 후

- **예전 HTML 파일은 더 이상 쓰지 마세요.** 예전 파일은 `latest` 탭에 저장하므로 새 웹과 데이터가 갈라집니다.
- 기존 `latest` · `history` 탭은 원본 보관용으로 남겨두세요(지워도 앱에는 영향 없음).

## 6. 사용 시 참고

- **처음 열 때 느릴 수 있음**: Render 무료 요금제는 15분 동안 아무도 안 쓰면 잠들고, 다시 깨어나는 데 1분 정도 걸립니다. 데이터는 구글 시트에 있으므로 사라지지 않습니다.
- **부(1부·2부·3부…)는 날짜마다 따로입니다.** 부를 추가하거나 삭제하면 지금 보고 있는 날짜에만 적용되고 다른 날짜에는 영향이 없습니다. (예전 HTML 버전은 부를 지우면 모든 날짜에서 같이 지워졌습니다) 부 개수가 따로 기록되지 않은 예전 날짜는 3부로 보입니다.
- **화면 위 노란 안내창**이 뜨면 저장이 멈춘 상태입니다. 안내 문구의 버튼(다시 불러오기 / 최신 데이터 불러오기)을 누르세요.
- **더보기(☰) 메뉴**
  - **🧾 정산**: 새 정산 · 정산 이력
  - **📁 정산관리** (눌러서 펼침): 정산결과 다운(보고 있는 날짜의 최종 처리금액표 CSV) / 백업 만들기 / 백업 목록(복원·삭제) / 전체 데이터 다운로드(모든 날짜 JSON, 관리자 페이지에서 다시 가져오기 가능)
  - **다크 모드**
- **날짜 탭**: 날짜가 많아도 한 줄로 유지되고 옆으로 밀어서(PC는 ‹ › 버튼) 봅니다. 고른 날짜는 자동으로 보이는 위치로 스크롤됩니다.
- **📅 N (전체 날짜 목록)**: 모든 날짜를 세로 목록으로 보고, 검색(띄어쓰기·대소문자 무시, Enter로 첫 결과 열기)해서 바로 이동합니다. 숨긴 날짜는 목록 아래 "숨긴 날짜"에서 바로 숨김 해제할 수 있습니다.
- 모바일에서는 탭 이름이 길면 말줄임(…)으로 줄여 보여줍니다. 전체 이름은 📅 목록에서 보입니다.
- 시트를 직접 고치고 싶다면 앱을 모두 닫은 상태에서 고친 뒤 앱을 새로고침하세요. (참고) 열은 고쳐도 다시 계산됩니다.

## 7. 개발자용

```bash
npm install
npm test          # 데이터 무손실·충돌·백업·구글 API 형식 테스트
npm run dev       # 구글 연결 없이 가짜 시트로 실행 → http://localhost:3000
```

| 파일 | 역할 |
|---|---|
| `server.js` | Express 서버, API |
| `lib/schema.js` | 탭 구조 정의, state ↔ 시트 행 변환(무손실 검증 포함) |
| `lib/store.js` | 저장/불러오기, 잠금, 버전 충돌, 쓰기 전·후 검증, 백업, 이전 |
| `lib/legacy.js` | 예전 `latest` JSON 읽기·변환·비교 |
| `lib/settle.js` | 정산 이력 탭 구조 |
| `lib/sheets-google.js` | 구글 Sheets API 연결 |
| `lib/sheets-memory.js` | 테스트용 가짜 시트 |
| `public/js/calc.js` | 정산 계산(화면과 동일한 규칙, 서버에서 settlement 탭 작성에 사용) |
| `public/js/app.js` | 화면(예전 HTML 스크립트 + 서버 동기화) |
| `public/admin.html` | 관리자: 연결 확인, 데이터 이전 |
